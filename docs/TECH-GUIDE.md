# 自媒体助手 · 技术选型与编程规范指南

> 用途：给人查阅，也给 AI 编程助手（Claude Code、Cursor 等）在写代码前读。
> 这里记的是「为什么这么选、什么情况下换、写代码要守哪些规矩」。具体模块在哪、一次请求怎么走，见 `docs/ARCHITECTURE.md`；日常约定的精简版见 `CLAUDE.md`。
> 最后整理：2026-10。数据和版本会过时，涉及「现在谁最流行」的结论，引用前请重新核对。

## 0. 一页结论

| 层 | 现在用的 | 结论 | 什么时候再考虑换 |
|---|---|---|---|
| 语言 | 前后端都是 JavaScript（Node.js ≥ 22） | 保持。逐步加 TypeScript | 团队主力只会 Python 且要长期自己写后端 → 逐步迁 Python（见 §3.4） |
| 前端框架 | Vue 3 + Pinia + Vite（大部分界面仍是 `public/js` 原生模块） | 保持 Vue 3，按 §2.3 一块块迁 | 主做海外、要原生级 App → 新 App 用 React Native |
| 后端框架 | Fastify 5（目前只当接连接的外壳，路由仍是自己的路由表） | 保持，逐步把路由注册、参数校验交给 Fastify | 团队 5 人以上、业务复杂 → NestJS |
| 数据库 | PostgreSQL + Drizzle ORM | 保持 | — |
| 队列 / 缓存 | Redis + BullMQ | 保持 | — |
| 文件 | 服务器本地磁盘 `data/` | 迁对象存储（阿里云 OSS / 腾讯云 COS） | 有了存储账号就做 |
| 模型调用 | 官方 SDK + 自研 `server/llm.js` | 保持，不引入 LangChain | — |
| 智能体流程 | 无 | 需要时用 LangGraph.js，模型调用仍走 `llm.js` | 做「自动选题→写→检查→重写→人工确认」流水线时 |
| 重计算（音视频、数据分析、本地模型） | 无 | 需要时加一个 Python + FastAPI 小服务 | 做 §3.5 里的功能时 |
| 移动端 | 网页（有窄屏适配） | 先 H5/PWA，再按 §7 选 uni-app 或 Capacitor | 口播录制要用手机拍时 |

判断原则（按重要性）：

1. **团队熟什么**比「哪个技术更好」重要得多。
2. **瓶颈在模型调用**：一次成稿要等模型几秒到几十秒，服务器自己处理只有几毫秒。换语言、换框架不会让用户觉得变快。
3. **逐步迁移，不推倒重来**：每一步都能单独上线、随时停下。
4. **少依赖**：加一个依赖就多一份升级和出问题的面。加之前问一句「不加行不行」。
5. **国内环境**：招人、小程序、支付、云服务都以国内生态为准。

## 2. 前端

### 2.1 Vue 3 还是 React

| 对比项 | React | Vue 3 |
|---|---|---|
| 写法 | JSX，界面写在 JS 里 | 模板，接近 HTML |
| 数据更新 | `useState` 显式通知，有时要手动优化重复渲染 | 响应式，改变量页面自动更新 |
| 学习成本 | 较高（Hooks、依赖数组、闭包陷阱） | 较低（会 HTML/JS 就能写） |
| 官方配套 | 路由、状态管理要自己选 | Vue Router、Pinia、Vite 官方一套 |
| 全球使用 | 更多 | 较少 |
| 国内使用 / 招人 | 大厂、出海多 | 更多，最好招 |
| 原生 App | React Native（体验好） | uni-app（小程序最方便）、Capacitor |
| 效果上限 | 浏览器能做的都能做 | 同左 |

**结论：本项目用 Vue 3。** 理由：国内用户和团队、将来要出微信小程序（uni-app）、模板写法和现有 HTML 最接近、编辑器和表单为主的界面用响应式数据最省事。
只有主做海外、或要做体验要求很高的原生 App 时，才值得另起一个 React Native App（后端接口共用）。

补充：
- 「Vue」现在默认指 Vue 3。Vue 2 已于 2023 年底停止维护，不要再用。
- Vue 3 用 Composition API（`<script setup>`），状态用 Pinia，构建用 Vite。

### 2.2 现状（2026-10）

- Vue 3 挂载页面，Pinia 的 store 就是旧代码里的 `state`（同一个对象）。
- **大部分界面仍由 `public/js/*.js` 按 id 找元素、拼 HTML**；`.vue` 文件多数是静态标记。
- 已真正由 Vue 渲染的：顶栏的模型标识和余额（`web/src/components/TopBar.vue`）。
- 构建：`npm run build:web` → `dist/`（每次清空、不进 git），服务端从 `dist/` 出首页和 `/assets/*`。

### 2.3 迁移到 Vue 的规则（必须遵守）

1. **一个节点只能归一方管。** 归 Vue（模板里有 `{{ }}` / `v-if` / `v-for` / `:class`）的，功能模块只改 store 的数据，不许再 `innerHTML` / `classList`；归 `public/js` 的，不许在上面加 Vue 绑定。两边都管会导致：Vue 重渲染抹掉模块写进去的内容，模块手里的元素引用指向已被替换的旧节点。
2. 迁一块的步骤：store 加字段 → 组件模板读它 → 模块里改 DOM 的代码换成写 store → 删掉 `core.js` 里 `el` 的对应项 → 补浏览器测试。
3. 顺序（从易到难）：任务数角标 → 左侧列表（创作记录、账号）→ 三个方向 → 各个弹窗 → 编辑器和口播。
4. 业务逻辑和界面分开：接口调用、数据整理写成不依赖框架的普通 JS 模块。将来做小程序或 React Native App 时这部分能直接复用。

## 3. 后端

### 3.1 语言对比：Node vs Python vs Java

| 对比项 | Node.js（现在） | Python（FastAPI） | Java（Spring Boot） |
|---|---|---|---|
| 和前端 | 同一种语言，部分代码可共用 | 两种语言 | 两种语言 |
| 流式输出 / 大量长连接 | 最擅长 | 能做好（async，注意别混同步慢操作） | 能做，写法繁琐 |
| 纯代码执行速度 | 快（V8 即时编译） | 慢几倍（但 numpy、PyTorch 等底层是 C，重计算反而快） | 快 |
| 简单接口吞吐 | 高 | 中 | 高 |
| AI / 数据 / 音视频生态 | 一般 | 最强 | 一般 |
| 开发速度 | 快 | 快 | 慢（样板代码多，同样功能 2～3 倍代码量） |
| 内存 / 部署 | 小，简单 | 小，要管 Python 环境 | 大（JVM），启动慢 |
| 学习成本 | 和前端一起学 JS 即可 | 语法最简单；异步、环境管理有坑 | 最高 |
| 生成文案的效果 | 一样（取决于模型、提示词、校验） | 一样 | 一样 |

结论：
- **性能**：Node 更好，也更适合本项目大量流式输出的场景；但瓶颈在模型调用，用户感受不到差别。
- **效果**：调用模型的效果三者一样；要在自己服务器上做 AI / 数据的重活时 Python 明显更好。
- **本项目**：主服务保持 Node。

### 3.2 后端框架怎么选

| 语言 | 框架 | 适合 |
|---|---|---|
| Node | Express | 小项目、老项目；设计偏老 |
| Node | **Fastify**（本项目） | 中小项目首选：快、自带参数校验和日志、插件体系 |
| Node | NestJS | 5 人以上、业务复杂、要严格分层（写法像 Spring） |
| Node | Hono | 小型 API、Serverless / 边缘节点 |
| Python | **FastAPI** | AI 应用、API 服务首选 |
| Python | Django | 要现成后台、内容管理 |
| Python | Flask | 小工具、原型 |
| Java | Spring Boot | 企业客户、政企、大团队、对接现有 Java 系统 |
| Go | Gin | 高并发网关、基础服务 |

快速决策：小团队 + 调 AI 接口 + 前后端一个人写 → Node + Fastify；AI + 数据分析 / 本地模型 → Python + FastAPI；卖给大企业 → Spring Boot。

### 3.3 本项目后端的下一步

- 把路由从自己的正则表更换为 Fastify 路由注册，参数用 JSON Schema 校验（现在每个接口手写 `String(body?.x)` 清洗）。
- 逐步加 TypeScript（先 `// @ts-check` + JSDoc，再改 `.ts`），类型错误在写代码时发现。

### 3.4 熟悉 Python、不熟 Node 怎么办

- 前端一定是 JS，所以 JS 至少要学到能读懂项目代码（2～4 周）。
- 主要让 AI 写代码、自己审：保持 Node。
- 长期自己写大量后端、且要做数据 / 音视频：可以迁 Python，但**不要一次性重写**：
  1. 新功能用 FastAPI 写成独立服务，nginx 按路径分流（例如 `/api/v2/*`）；
  2. 两个服务共用一个数据库和登录态；
  3. 旧接口按模块逐个搬（先简单的：素材库、选题池、复盘；最后搬成稿流式、计费、支付、任务队列），每搬一个用现有测试核对；
  4. 搬完再下线 Node。

### 3.5 适合引入 Python 的功能

| 优先级 | 功能 | 现在 | 用 Python 后 | 常用库 |
|---|---|---|---|---|
| 1 | 素材召回 | 字面关键词匹配 | 按意思匹配（「省时间」能找到「效率」） | bge-m3 等中文向量模型 + pgvector |
| 2 | 文件导入（范文、旧文章、语气样本） | 只能粘文字 / txt / md | 直接传 Word、PDF、截图 | python-docx、pdfplumber、PaddleOCR |
| 3 | 口播细节分析 | 网关打分 | 本地补语速、停顿、口头禅、音量，精确到秒 | librosa、parselmouth |
| 3 | 本地语音转写（可选） | 网关 | 自部署省钱，拿到逐字时间戳 | FunASR、Whisper |
| 3 | 口播视频自动加字幕 | 无 | 按时间戳压字幕，导出成片 | ffmpeg、moviepy |
| 4 | 复盘多因素分析 | 分组比中位数 | 标题长度、字数、时间、框架、方向各自影响多大 | pandas、statsmodels、scikit-learn |
| 4 | 防洗稿 | 连续 8 字相同 | 识别换词、调语序的改写 | jieba + SimHash / 向量相似度 |
| 5 | 语气量化、违禁词分词、配图后期、热点正文提取、标题效果预测 | — | — | jieba、Pillow、trafilatura、scikit-learn |

接入方式：Python 服务只在内网被 Node 调用；耗时的走现有任务队列（Node 登记任务，worker 调 Python，结果写回库），任务中心、重试、计费全部复用。Python 服务最好只收数据、回结果，不直接写库。

注意：出镜评测按网关规范整段视频交给网关，**不要在本地抽帧**。

不适合搬到 Python 的：调大模型和流式成稿（`llm.js` 连着计费）、登录计费支付、任务队列本身。

## 4. 数据库、队列、存储

| 组件 | 选择 | 理由 / 规矩 |
|---|---|---|
| 主库 | PostgreSQL | 多进程、多机、事务、全文检索、将来的 pgvector 都支持。SQLite 只适合单机单进程 |
| ORM | Drizzle | 轻、SQL 可控。表结构只通过 `server/migrations.js` 末尾追加编号迁移来改，同步 `server/schema.js` |
| 队列 | Redis + BullMQ | 长任务（出图、口播评测）。**任务状态以 PostgreSQL 为准**，Redis 只放任务号，丢了能按表补投 |
| 文件 | 现在本地 `data/`，计划迁对象存储 | 多机部署、CDN、备份都需要 |
| 向量检索 | 需要时用 pgvector | 不另起向量数据库 |

从 SQLite 换到 PostgreSQL 后必须注意（踩过的坑）：
- SQLite 同步执行，请求天然排成一列；**PostgreSQL 会并发**。「先查再改」的地方要么写成一条带条件的 UPDATE，要么放进事务并 `SELECT … FOR UPDATE`。
- 防重复靠**唯一索引**（必要时用部分唯一索引，如「同一件事只能有一个在跑的任务」），插入用 `ON CONFLICT DO NOTHING`，冲突回 409。
- 多条语句必须一起成功的，放进 `withTx`；多个事务按同一顺序加锁（先锁稿子再动历史版本），避免死锁。
- 连接池要有 `error` 监听、连接超时、语句超时，否则数据库一抖整个进程退出或请求永远挂起。

## 5. AI 层：LangChain、LangGraph、fastai

| 名称 | 是什么 | 本项目 |
|---|---|---|
| FastAPI | Python 的 Web 框架（接口层），不是 AI 库 | 只在加 Python 小服务时用 |
| fastai | 基于 PyTorch 的深度学习训练库 | 用不上（不训练模型） |
| LangChain | 大模型应用库：统一调用各家模型、提示词模板、RAG、工具调用 | **不用**。`llm.js` 已做多模型切换、分档、重试、超时、计费、用量统计，比它更贴合业务；LangChain 抽象厚、版本变化快、计费需要的准确 token 数不一定拿得全 |
| LangGraph | 多步智能体流程编排：分支、循环、人工确认、断点续跑、状态保存 | **将来用 LangGraph.js**：做自动化流水线（热点→选题→写稿→检查→不合格自动重写→人工确认）时引入；每一步调模型仍走 `llm.js` |

从零做 AI 项目的推荐：简单调模型 → 官方 SDK；知识库问答 → SDK + 向量库；多步流程 → LangGraph；接口层 → FastAPI / Fastify；训练模型 → PyTorch。

模型层规矩（不论用什么框架都要守）：
- 所有模型调用经过一个统一入口（本项目 `llm.js` 的 `generateJSON` / `generateText` / `streamText`），带 `feature` 和 `userId`，才能计费、限流、统计。
- 额度**先预扣再结算**（`reserve` → `settle`），失败退回，中断按已生成部分收。
- **模型输出不可信**：引用原文的字段必须能逐字找到，结构不全重试一次，不信模型给的分数和金额。
- 外部内容（用户素材、热点、抓取的原文、转写）进提示词时用标签包起来当资料（`fence`），不能让它改写指令。
- 提示词有版本、能在线改、能做 A/B；效果用真实行为数据评估（改稿比例、检查建议采纳率），不只看人工打分。

## 6. 部署与运维

- 形态：nginx 反代 + pm2（单实例）+ PostgreSQL + Redis，部署脚本 `scripts/deploy-jdcloud.sh`；前端在本机构建，`dist/` 整目录同步。
- **优雅停机**：收到 SIGTERM 先停止接新请求，等进行中的流式成稿、上传、后台任务做完（约 30 秒），再断开 Redis 和数据库；pm2 的 `kill_timeout` 要大于这个时间。
- 依赖挂了要能活：Redis 连不上服务照常启动，任务先记库里；数据库断开不能让进程退出。
- 密钥：`.env` 权限 600，不进 git；密码不出现在命令行参数和日志里；备份文件权限 600，最好再同步一份到异地。
- 以后多实例：去掉进程内的限流和每人并发计数（改用 Redis），Redis 键前缀按环境区分。

## 7. 移动端

### 7.1 技术路线

| 阶段 | 做法 | 能复用多少 | 说明 |
|---|---|---|---|
| 1 | **H5 / PWA**：现有网页做好窄屏适配，可「添加到主屏幕」 | 几乎全部 | 最快。现有样式已有多处窄屏断点，提词器和录音已能在浏览器里用 |
| 2a | **Capacitor** 把网页打包成 iOS / Android App | 几乎全部（现有 DOM 代码也能跑） | 能用原生相机、录像、推送、文件；体验偏网页 |
| 2b | **uni-app**（Vue）出微信小程序 + App | 只能复用真正的 Vue 组件和纯逻辑模块 | 小程序里没有 DOM，`public/js` 那套按 id 改元素的代码用不了，要先完成 §2.3 的迁移 |
| 3 | React Native 原生 App | 只复用后端接口 | 只有 App 成为主打产品、有专人负责时才值得 |

注意：面向公众上线生成式 AI 服务（尤其是小程序、应用商店），国内有备案、内容安全等合规要求，立项前先确认资质和流程。

### 7.2 适合放到移动端的功能

按「手机上做比电脑上顺手」排序：

| 优先级 | 功能 | 为什么适合手机 | 要点 |
|---|---|---|---|
| ★★★ | **口播录制 + 提词器** | 口播本来就用手机拍；这是和纯文案工具拉开差距的地方 | 手机上要**录视频**（出镜评测需要画面，现在网页提词器只录音）；前置摄像头 + 滚动提词 + 防息屏；录完自动上传走任务队列 |
| ★★★ | **口播评测结果** | 拍完马上看哪句漏了、哪里语速快、出镜怎么样，再拍一遍 | 分数 + 可点回对应句子；任务完成推送通知 |
| ★★★ | **灵感和素材随手记** | 灵感、真实经历、数据都在碎片时间出现 | 语音 / 文字 / 拍照三种入口 → 进选题池或素材库；语音可转文字 |
| ★★☆ | **热点速览 → 存选题池** | 刷热点是手机行为 | 列表 + 一键「存起来」「现在写」 |
| ★★☆ | **快速出稿**：题材 → 三个方向 → 成稿 | 通勤时出一篇短稿（小红书、微博、口播稿） | 以阅读和轻改为主；一键复制，跳到小红书 / 公众号 App 去发 |
| ★★☆ | **语音改稿** | 手机上打字慢，说一句「第二段改得口语一点」更快 | 已有能力，做成按住说话的大按钮 |
| ★★☆ | **发布数据回填 + 复盘看板** | 发完在手机上看数据最方便 | 发布后第 1 天、第 7 天推送提醒回填；看板只读 |
| ★☆☆ | 任务中心、配图预览与保存到相册、标题候选挑选 | 等出图、挑标题都是轻操作 | — |
| ★☆☆ | 快速建号（贴自我介绍） | 新用户第一次打开多半在手机上 | 只做「贴一段话」的入口，细节去电脑上改 |

**留在电脑上的**（手机上做反而难受）：长文精细编辑和排版、多平台版本对照、框架库编辑与范文拆解、账号设定的完整编辑、语气样本管理、管理后台、提示词编辑、A/B 与 Eval、导出 Word / PDF。手机上这些入口可以只读或直接提示「请在电脑上操作」。

建议的第一版移动端范围：**口播录制与评测 + 灵感速记 + 热点存选题 + 快速出稿（读和复制）+ 数据回填**。先用 H5 验证使用频率，再决定走 Capacitor（快）还是 uni-app 小程序（要先完成 Vue 迁移）。

## 8. 代码架构规范

### 8.1 分层（后端）

```
server/index.js          接连接、路由表、静态文件、停机
server/routes/<域>.js    接口处理：校验输入 → 调业务 / 数据层 → 返回。一个业务域一个文件
server/routes/common.js  共用小工具（json、requireUser、withRetry…），不能 import 其他业务域
server/<能力>.js         业务能力：llm.js（模型）、jobs.js（队列）、quota.js（额度）、speak.js、images.js…
server/db.js             数据访问（每张表一个 DAO 对象），只做存取，不写业务判断
server/schema.js + migrations.js   表结构（改表只追加迁移）
server/prompts.js        全部提示词和 user 消息拼装
```

规矩：
- 新接口：`server/index.js` 的 `ROUTES` 加一行，处理函数写在 `server/routes/<域>.js` 并 `export`。
- 依赖方向单向：路由 → 能力 → 数据层；数据层不 import 路由，`common.js` 不 import 业务域。
- 要跑很久的活：用 `jobs.js` 的 `defineJob` / `enqueue`，接口立刻返回任务，不在请求里等。
- 新增一个模型功能要同时：`llm.js` 的 `FEATURE_TIER` 定档、`plans.js` 的 `TEXT_FEATURES` 登记、有提示词的在 `promptrev.js` 和 `promptdocs.js` 登记。

### 8.2 分层（前端）

- 页面结构：`web/src/components/*.vue`，由 `App.vue` 拼起来。
- 共享状态：Pinia store（`web/src/stores/studio.js`），旧模块通过 `core.js` 的 `state` 读写同一份。
- 旧功能模块：`public/js/<模块>.js`；`core.js` 不 import 功能模块。
- 模块间「通知」用 window 事件（`cw-spent`、`cw-quota`、`cw-enter`、`cw-job-done`），「调用」用 import。
- 迁移规则见 §2.3。

### 8.3 目录与命名

- 文件名小写、按业务命名（`frameworks.js`、`jobs.js`），不按技术分层命名（不要 `utils2.js`、`helpers.js` 堆杂物）。
- 函数名说清做什么：`handleXxx`（接口）、`XxxUser` / `XXX_SYSTEM`（提示词）、DAO 方法用动词（`byId`、`list`、`create`、`setStatus`）。
- 常量全大写（`MAX_ATTEMPTS`、`FRAMEWORK_LIMITS`）；可配置的写进 `.env.example` 并注释默认值。

## 9. 代码注释与文档规范

- **语言**：注释、界面文案、README、文档用中文；git 提交信息用英文（祈使句，首行 ≤ 72 字符，正文说明「改了什么、为什么」）。
- **写「为什么」，不写「是什么」**：代码本身能看出做了什么；注释要写代码看不出来的——设计取舍、踩过的坑、业务规则的来由、不这么写会出什么事。
  - 好：`// 跨月重置只做一次：带上「还是旧周期」的条件，否则并发请求会在别人预扣后把 used 清零（实测过）`
  - 差：`// 更新 used 为 0`
- **每个文件开头一段块注释**：这个文件管什么、关键设计、和谁配合（参考 `server/jobs.js`、`server/quality.js`）。
- **每个导出函数 / 接口前一句话**：做什么、输入输出里容易误解的地方、副作用（扣钱、写库、发请求）。
- **不信任外部数据的地方必须注明**（模型输出、用户输入、第三方回调），说明校验方式。
- **临时方案标出来**：`// 临时：…，等 … 之后改成 …`，别让临时变永久。
- **文档同步**：
  - 改接口 → 更新 README 的 API 表；
  - 改架构、加模块 → 更新 `docs/ARCHITECTURE.md`；
  - 改提示词 → 更新 `server/promptdocs.js`（提示词说明书）；
  - 改开发约定 → 更新 `CLAUDE.md`；
  - 选型变化 → 更新本文件。
- 文档只写真实情况。做了一半的事写「现状 + 下一步」，不要写成已经完成。

## 10. 编码规范

### 10.1 异步（最容易出事）

- 数据层全部是 async：**调用一律 `await`**。
- 对异步结果调方法要加括号：`(await Dao.list()).map(...)`，不能写 `await Dao.list().map(...)`（`.map` 先于 `await` 执行）。
- 不含 `await` 的函数不要标 `async`（放进 `.map` 会得到一组 Promise，存进库就变成 `{}`）。
- 故意不等的写 `void task().catch(log)`，或在行尾加 `// no-await-ok` 并说明原因。
- `scripts/check-async.js` 会在 `npm test` 时检查以上几条。

### 10.2 数据一致性与并发

- 「先查再改」改成「带条件的一条 UPDATE」或「事务 + `FOR UPDATE`」。
- 防重复用唯一索引 + `ON CONFLICT`，冲突回 409。
- 钱相关：金额只从服务端套餐表算；支付回调验签；发货只在订单从 pending 变 paid 时做一次。

### 10.3 错误处理

- 业务错误抛 `HttpError(状态码, 中文提示)`；额度不足抛 `QuotaError`（402，带用量信息）。
- 不把内部错误原文、堆栈给用户；5xx 在服务端记日志。
- 外部服务（模型、网关、Redis、数据库）失败要有超时、重试或降级，不能让请求永远挂着。

### 10.4 安全

- 拼 HTML 一律先 `esc()`；Markdown 用 `markdown()`（先转义再加标签）。前端不用 `v-html` 渲染未转义内容。
- 不读取、打印、提交 `.env` 和 `data/`；密码不进命令行参数、日志、git。
- 用户文件只能本人访问（`serveOwned`）。
- 在 nginx 后面取客户端 IP 用 `X-Real-IP`，不信 `X-Forwarded-For` 最左一段。

### 10.5 测试

- 改完跑 `npm test`（需要本机 PostgreSQL、Redis）；不通过不提交。
- 单测测纯函数和数据层；**接口改动在 `tests/routes.test.js` 补一条真实 HTTP 测试**——数据层异步化时漏 await 的一批 bug，单测全绿，只有接口测试拦得住。
- 浏览器流程（注册→成稿→改写→配图→口播→复盘）在大改前后用 Playwright 走一遍。
- 测试不读 `.env`，用演示模式和独立 schema。

## 12. 什么情况下重新评估选型

| 触发条件 | 重新考虑 |
|---|---|
| 要在服务器上跑语音、视频、数据分析、本地模型 | 加 Python + FastAPI 小服务 |
| 团队主力换成 Python，且后端改动频繁 | 按 §3.4 逐步迁 Python |
| 团队超过 5 人、模块间边界经常打架 | 后端 NestJS，前后端上 TypeScript |
| 要做微信小程序 | 先完成 Vue 迁移，再上 uni-app |
| App 成为主打产品、有专人负责 | React Native 或原生 |
| 要做多步自动化创作流水线 | LangGraph.js（模型调用仍走 `llm.js`） |
| 同时在线上千、单机扛不住 | 多实例：限流和并发计数挪到 Redis，文件上对象存储，数据库读写分离 |
| 卖给要求 Java 技术栈的企业客户 | 评估 Spring Boot（通常只做对接层） |
