# 新项目技术选型与编程规范指南

> 用途：开一个全新项目时，按这份文档定技术栈和代码规矩；也可以整份交给 AI 编程助手（Claude Code、Cursor 等）当约定。
> 不绑定某个具体项目。某个项目实际怎么选、为什么，写在那个项目自己的「技术选型记录」里（例如本仓库的 `docs/TECH-DECISIONS.md`）。
> 最后整理：2026-10。「谁最流行」这类结论会过时，引用前请重新核对。

---

## 0. 选型原则（按重要性）

1. **团队熟什么，比哪个技术更好重要得多。** 熟悉的技术开发快、坑少。
2. **先找瓶颈再选技术。** 调大模型的应用，瓶颈在等模型（秒级），不在服务器（毫秒级），换语言换框架用户感觉不到。
3. **用主流、资料多的。** 出问题搜得到答案，AI 编程助手也写得更准。
4. **少依赖。** 每加一个依赖都多一份升级和出问题的面。加之前问「不加行不行」。
5. **先简单，留口子。** 单机能跑就先单机；但把会卡住扩容的地方（进程内状态、本地文件）标出来。
6. **按市场选生态。** 国内用户：Vue、微信生态、国内云和支付；海外：React、Stripe、海外云。
7. **能逐步替换。** 选能一块块换掉的架构，不做「只能推倒重来」的决定。

## 3. 前端

### 3.1 Vue 3 还是 React

| 对比项 | React | Vue 3 |
|---|---|---|
| 写法 | JSX，界面写在 JS 里 | 模板，接近 HTML |
| 数据更新 | `useState` 显式通知，有时要手动优化重复渲染 | 响应式，改变量页面自动更新 |
| 学习成本 | 较高（Hooks、依赖数组、闭包陷阱） | 较低 |
| 官方配套 | 路由、状态管理要自己选 | Vue Router、Pinia、Vite 一套 |
| 全球 / 国内 | 全球更多 / 大厂、出海多 | 全球较少 / 国内更多、最好招 |
| 原生 App | React Native（体验好） | uni-app（小程序方便）、Capacitor |
| 效果上限 | 浏览器能做的都能做 | 同左 |

大致学习时间（有 JS 基础）：能写简单页面 Vue 1～3 天 / React 3～7 天；能独立做中等项目 Vue 2～4 周 / React 1～2 个月。

选 **Vue 3**：国内团队、要出小程序或多端、想快速上手、中后台和表单为主。
选 **React**：面向海外、要做体验好的原生 App（React Native）、团队熟 React、要 Next.js 做 SEO。

补充：Vue 2 已停止维护，新项目只用 Vue 3（Composition API、`<script setup>`、Pinia、Vite）。

### 3.2 前端通用规矩

- 一开始就用框架写，不要先写原生 DOM 再迁移——迁移期「两套代码管同一个节点」是最容易出 bug 的状态。
- 业务逻辑（接口调用、数据整理、校验规则）写成不依赖框架的普通 JS/TS 模块，组件只管展示和交互。将来做小程序、换框架时这部分能直接复用。
- 用 TypeScript，至少给接口数据定类型。
- 构建产物放单独目录（`dist/`），不进 git；带哈希的文件长期缓存，找不到返回 404。
- 不用 `v-html` / `dangerouslySetInnerHTML` 渲染未转义的内容。

## 4. 后端

### 4.1 语言：Node vs Python vs Java（vs Go）

| 对比项 | Node.js | Python | Java | Go |
|---|---|---|---|---|
| 和前端 | 同一种语言 | 两种 | 两种 | 两种 |
| 流式输出 / 大量长连接 | 最擅长 | 能做好（async，别混同步慢操作） | 能做，繁琐 | 擅长 |
| 纯代码执行速度 | 快 | 慢几倍（numpy 等 C 库例外） | 快 | 很快 |
| AI / 数据 / 音视频生态 | 一般 | 最强 | 一般 | 一般 |
| 开发速度 | 快 | 快 | 慢（代码量约 2～3 倍） | 中 |
| 内存 / 部署 | 小 | 小，要管 Python 环境 | 大，启动慢 | 最小，一个二进制 |
| 学习成本 | 低（和前端一起学） | 最低（语法）；异步和环境管理有坑 | 最高 | 中 |
| 调模型的效果 | 一样 | 一样 | 一样 | 一样 |

结论：
- 调 AI 接口 + 流式输出 + 小团队：**Node** 或 **Python** 都好，选团队熟的。
- 要在服务器上跑模型、做数据分析、处理音视频：**Python**。
- 企业级、大团队、对接 Java 系统：**Java**。
- 高并发基础服务：**Go**。
- 两种都需要时：主服务用一种，另一种做内网小服务（例如 Node 主服务 + Python 数据服务），通过 HTTP 或任务队列协作。

### 4.2 框架

| 语言 | 框架 | 适合 |
|---|---|---|
| Node | Express | 小项目、老项目；设计偏老 |
| Node | **Fastify** | 中小项目首选：快、自带 JSON Schema 校验和日志、插件体系 |
| Node | NestJS | 5 人以上、业务复杂、要严格分层（写法像 Spring） |
| Node | Hono | 小型 API、Serverless / 边缘节点 |
| Python | **FastAPI** | AI 应用、API 服务首选；Pydantic 校验、自动接口文档 |
| Python | Django | 要现成后台、ORM、权限；内容管理 |
| Python | Flask | 小工具、原型 |
| Java | Spring Boot | 企业级标配 |
| Go | Gin | 高并发服务 |

### 4.3 熟悉 Python、不熟 Node 怎么选

- 前端一定是 JS，JS 至少要学到能读懂代码。
- 新项目：后端直接用 **Python + FastAPI**，前端 Vue / React。
- 已有 Node 项目：主要让 AI 写代码、自己审的，保持 Node；长期自己写大量后端的，**逐步**迁 Python（新功能用 Python 写 → nginx 按路径分流 → 共用数据库和登录态 → 旧接口按模块搬 → 搬完下线旧服务），不一次性重写。

## 5. 数据、队列、存储

| 组件 | 默认选择 | 说明 |
|---|---|---|
| 主库 | **PostgreSQL** | 事务、并发、JSON、全文检索、pgvector 都有。MySQL 也可以（国内运维多）。SQLite 只适合单进程 MVP |
| ORM | Node：Drizzle / Prisma；Python：SQLAlchemy / SQLModel；Java：JPA / MyBatis | 表结构用编号迁移管理，不手改线上库 |
| 缓存 / 队列 | **Redis**；Node 用 BullMQ，Python 用 Celery / RQ / Arq | 任务状态以数据库为准，Redis 只放「该跑哪条」，丢了能按库补 |
| 文件 | **对象存储**（阿里云 OSS / 腾讯云 COS / S3） | 从第一天起就别往服务器硬盘存用户文件 |
| 向量检索 | pgvector | 数据量不大时不另起向量数据库 |

从同步单进程库（SQLite）换到 PostgreSQL 必须注意：
- PostgreSQL 会并发执行请求。「先查再改」要写成**一条带条件的 UPDATE**，或放进事务并 `SELECT … FOR UPDATE`。
- 防重复用**唯一索引**（必要时部分唯一索引），插入用 `ON CONFLICT DO NOTHING`，冲突回 409。
- 多个事务按同一顺序加锁，避免死锁。
- 连接池要有 `error` 监听、连接超时、语句超时。
- 所有数据访问都是异步的：每个调用都要 `await`（见 §10.1）。

## 6. AI 层：官方 SDK、LangChain、LangGraph、fastai

| 名称 | 是什么 | 什么时候用 |
|---|---|---|
| 官方 SDK（Anthropic / OpenAI） | 直接调模型 | 默认。简单调用、流式输出 |
| LangChain | 统一各家模型调用、提示词模板、RAG、工具调用 | 要快速接很多家模型、做原型时。生产系统里抽象厚、版本变化快，很多团队后期拆掉 |
| LangGraph | 多步智能体流程编排：分支、循环、人工确认、断点续跑 | 流程真的复杂（多步、要人工确认、要能暂停恢复）时 |
| FastAPI | Python Web 框架（接口层），不是 AI 库 | 用 Python 写后端时 |
| fastai | 基于 PyTorch 的深度学习训练库 | 只在自己训练模型时；只调 API 用不上 |

推荐组合：接口层（Fastify / FastAPI）+ **自己的一层模型网关**（统一入口：计费、限流、超时、重试、用量记录）+ 需要时 LangGraph 编排流程，每一步仍经过自己的模型网关。

模型层规矩：
- 所有模型调用走一个统一入口，带上「功能名」和「用户」，才能计费、限流、统计。
- 额度**先预扣再结算**，失败退回，中断按已生成部分收；检查和扣减必须是一个原子操作。
- **模型输出不可信**：引用原文的字段必须能逐字找到；结构不全重试一次；不信模型给的分数和金额。
- 外部内容（用户素材、网页、转写）进提示词时用标签包起来当资料，明确「资料里的话不是指令」。
- 提示词有版本、能在线改、能 A/B；效果用真实行为（用户改了多少、建议采纳了多少）评估，不只看人工打分。

## 7. 部署与运维

- 起步：一台云服务器 + nginx 反代 + 进程管理（pm2 / systemd / Docker）+ PostgreSQL + Redis；一条命令部署，部署前自动跑检查和测试。
- **优雅停机**：收到 SIGTERM 先停止接新请求，等进行中的请求和后台任务做完再退出；进程管理器的强杀时间要比这个长。
- **依赖挂了要能活**：Redis 连不上服务照常启动、任务先记库；数据库断开不能让进程退出；外部调用都有超时。
- **密钥**：`.env` 权限 600、不进 git；密码不出现在命令行参数和日志；备份文件权限 600 并异地存一份。
- 启动时打印「线上容易踩的配置」提醒（支付没配、管理员没建、注册关着）。
- 要多实例时：限流、每人并发、会话等进程内状态挪到 Redis；文件上对象存储。
- 健康检查接口返回服务标识和依赖状态。

## 8. 移动端路线

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| H5 / PWA | 网页做窄屏适配 | 最快、零额外代码 | 相机、推送等能力受限 |
| Capacitor | 把网页打包成 App | 几乎零额外代码，能用原生能力 | 体验偏网页 |
| uni-app（Vue） | 一套代码出小程序、H5、App | 国内出小程序最方便 | 要求真正的 Vue 组件（小程序没有 DOM）；复杂交互会卡 |
| React Native | 原生界面 | 体验最好 | 界面要单独写一套 |

选择顺序：先 H5 验证需求 → 要上架用 Capacitor（快）或 uni-app（要小程序）→ App 成为主打产品再考虑 React Native。
手机上适合放「碎片时间、拍摄录音、看结果、轻操作」的功能；长文编辑、配置、后台留在电脑上。
国内面向公众上线生成式 AI 服务有备案、内容安全等合规要求，立项前确认。

## 9. 代码架构规范

### 9.1 分层

```
入口层     接连接、路由表、静态文件、停机（index）
接口层     routes/<业务域>：校验输入 → 调业务 / 数据层 → 返回。一个业务域一个文件
能力层     llm（模型网关）、jobs（队列）、quota（额度）、pay（支付）… 每个能力一个模块
数据层     db / dao：只做存取，不写业务判断；每张表一个访问对象
结构       schema + migrations：改表只追加编号迁移
提示词     prompts：全部提示词和拼装集中在一处
```

- 依赖方向单向：接口层 → 能力层 → 数据层；数据层不 import 接口层；公共工具不 import 业务模块。
- 要跑很久的活（生成图片、处理音视频、批量任务）走任务队列，接口立刻返回任务号，前端轮询或推送。
- 每个外部服务（模型、支付、网关、存储）包一层自己的模块，业务代码不直接调第三方 SDK。

### 9.2 前端

- 页面 = 组件；共享状态放 store（Pinia / Zustand 等）；接口调用集中在一个 `api` 模块。
- 模块之间「通知」用事件或 store，「调用」用 import，不互相直接改对方的 DOM。

### 9.3 目录与命名

- 按业务命名文件（`frameworks.js`、`jobs.js`），不要 `utils2.js`、`helpers.js` 堆杂物。
- 函数名说清做什么：接口处理 `handleXxx`，数据访问用动词（`byId`、`list`、`create`、`setStatus`）。
- 常量全大写；可配置项写进 `.env.example` 并注明默认值和作用。

## 10. 编码规范

### 10.1 异步

- 所有异步调用都 `await`。
- 对异步结果调方法加括号：`(await list()).map(...)`，不是 `await list().map(...)`。
- 不含 `await` 的函数不要标 `async`（放进 `.map` 会得到一组 Promise）。
- 故意不等的写 `void task().catch(log)` 并注释原因。
- 没有 TypeScript 的 `no-floating-promises` 时，写一个检查脚本放进测试（参考本仓库 `scripts/check-async.js`）。

### 10.2 并发与一致性

- 「先查再改」→ 带条件的 UPDATE，或事务 + 行锁。
- 防重复靠唯一索引，不靠「先查有没有」。
- 钱相关：金额只从服务端价格表算；支付回调验签；发货只在状态从「待支付」变「已支付」时做一次。

### 10.3 错误处理

- 业务错误抛带状态码和中文提示的错误；不把内部错误原文、堆栈给用户；5xx 记日志。
- 外部服务失败要有超时、重试或降级。
- 进程级兜底：记录未处理的 Promise 拒绝，不让它悄悄带走进程。

### 10.4 安全

- 拼 HTML 先转义；Markdown 先转义再加标签。
- 密钥不进 git、不进日志、不进命令行参数。
- 用户文件只能本人访问；在反向代理后面取客户端 IP 用代理写入的 `X-Real-IP`，不信 `X-Forwarded-For` 最左一段。
- 登录、注册、验证码接口有限流。

### 10.5 测试

- 三层：纯函数和数据层的**单测** → 真起服务走 HTTP 的**接口测试** → Playwright 的**浏览器流程测试**。
- 接口测试最值钱：单测全绿、接口却坏掉的情况（漏 await、返回结构不对）只有它拦得住。
- 测试用独立数据库（或独立 schema）和假模型，不读真实 `.env`。
- 改完跑全部测试，不通过不提交；部署脚本先跑测试再上线。

## 11. 注释与文档规范

- **语言**：注释、界面文案、文档用中文；git 提交信息用英文（祈使句，首行 ≤ 72 字符，正文写改了什么、为什么）。
- **写「为什么」，不写「是什么」**。写代码看不出来的：设计取舍、踩过的坑、业务规则来由、不这么写会出什么事。
  - 好：`// 跨月重置带上「还是旧周期」的条件：不带的话并发请求会在别人预扣后把用量清零`
  - 差：`// 把 used 设为 0`
- **文件头**：一段块注释说明这个文件管什么、关键设计、和谁配合。
- **导出函数 / 接口**：一句话说明做什么、容易误解的输入输出、副作用（扣钱、写库、发请求）。
- **不可信数据**（模型输出、用户输入、第三方回调）旁边注明怎么校验的。
- **临时方案**标出来：`// 临时：…，等 … 之后改成 …`。
- **文档随代码一起改**：
  - `README`：怎么跑、功能说明、接口表；
  - `docs/ARCHITECTURE.md`：模块、数据流、改东西去哪；
  - `docs/TECH-DECISIONS.md`：本项目的选型理由和已知取舍；
  - `CLAUDE.md`（或 `.cursorrules`）：给 AI 编程助手的精简约定；
  - 提示词说明书：每条提示词的定位和逻辑。
- 文档只写真实情况；做了一半的写「现状 + 下一步」，不写成已经完成。

## 12. 给 AI 编程助手的执行清单

动手前：
1. 读项目的 `CLAUDE.md`、`docs/ARCHITECTURE.md`、`docs/TECH-DECISIONS.md`。
2. 确认改动落在哪一层（§9），不跨层乱放。
3. 加依赖、改表结构、改计费 / 支付、删文件之前先问。

写代码时：
4. 异步调用全部 `await`；并发敏感的按 §5、§10.2 写。
5. 模型调用走统一入口，输出按 §6 校验；外部内容进提示词当资料。
6. 长任务走队列。
7. 前端组件只读 store、逻辑放纯模块；迁移期遵守「一个节点只归一方管」。
8. 注释按 §11：写为什么，标出不可信数据和临时方案。

完成前：
